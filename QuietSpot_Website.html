Hardware implementation

From sound to signal.

Proposed wiring for a classic ESP32 DevKit. Confirm board pinout before assembly.

MAX9814 VCC → 3.3 V, OUT → GPIO34, GND → common ground. Each GPIO drives one LED through its own 220 Ω resistor. Leave module gain/attack settings at their documented defaults initially. USB powers the development board.

Firmware: sample ADC1, remove DC bias, calculate RMS over a short window, smooth readings and classify using calibrated thresholds. Send table ID, activity and state over Wi-Fi; alert once on entry into red. Use a short persistence window and hysteresis to avoid false alerts.

Deployment: ESP32 → local Wi-Fi → local server or broker → librarian dashboard. This standalone HTML simulates that data path; a network receiver and ESP32 firmware are not included. MAX9814 automatic gain control limits accurate dB measurement; compare against the CEM DT-73S and report relative activity unless validated.

From observation to prototype

Make quiet easier to share.

Reminders help for a moment, but activity can rise again when the room gets busy.

01 / Notice

Sense sound activity

A microphone module estimates the room’s sound level locally. The concept does not need to capture or store speech.

02 / Signal

Offer a gentle cue

A simple green, amber, or red light can help visitors notice when the shared space is getting louder.

03 / Learn

Review the pattern

A red event sends the table ID and status to the librarian in the proposed connected system. The demo below simulates this workflow.
